# Agentic HQ Documentation

This directory contains all of Agentic HQ's documentation. New here? Start
with the top-level [`README.md`](../README.md) for setup and the Quick Start.

The folders are grouped below by audience. Live, maintained docs come first
(User, Developer); generated outputs and historical material are at the bottom
so they don't get in your way.

## User Documentation

For people who *use* `agentic-hq` — running shipped workflows from their own
workspaces.

- [`user-docs/workflow-descriptions/overview-of-workflows.md`](user-docs/workflow-descriptions/overview-of-workflows.md) —
  How to run each shipped workflow, with setup guides (e.g. the Sooperset
  Atlassian MCP server used by the Jira workflows). The authoritative list of live
  workflows can be seen by running `agentic-hq list`; this doc is the human-readable companion.
- [`user-docs/WARNING-re-auto-approved-claude-permissions.md`](user-docs/WARNING-re-auto-approved-claude-permissions.md) —
  Important warning listing the Claude Code, Jira, and Confluence tools that
  AHQ auto-approves when running workflows via the CLI.
- [`user-docs/troubleshooting-quickstart.md`](user-docs/troubleshooting-quickstart.md) —
  What to do if a step in the README Quick Start fails.

## Internal Artifacts

Outputs generated by running AHQ — not maintained documentation. Useful as
worked examples, but the contents are produced automatically, not edited by
hand.

- [`jira-docs/`](jira-docs/) — Per-Jira-ticket workflow execution records
  (37 `AHQ-N` folders, each with a `workflow-files/` subdirectory). Many AHQ
  features were implemented via the `full-jira-tdd-story-workflow`, which
  drops its plans, RED/GREEN/REFACTOR notes and validation results here.
- [`workflow-creation-docs/`](workflow-creation-docs/) — Per-workflow design
  and lifecycle docs, organised by plugin then by workflow.

## Historical

Preserved for reference, not actively maintained. Read with the assumption
that paths, decisions, and terminology may be out of date.

- [`ARCHIVED/`](ARCHIVED/) — Old project docs and pre-plugin-era artifacts
  from the BMAD/BUFD-style methodology used early in the project.
- [`LATER/`](LATER/) — Deferred ideas and speculative explorations
  (NOW/NEXT/LATER prioritisation), kept separate so they don't crowd
  current work.
