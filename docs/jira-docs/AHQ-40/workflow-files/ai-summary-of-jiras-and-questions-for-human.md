## Research Findings

### Git Root Detection Technique

Use `git rev-parse --show-toplevel` to detect the git root directory. This is the most robust approach:
- Uses git itself to answer "where's my repo root?"
- Handles edge cases like submodules (`.git` is a file, not a dir), worktrees, bare repos
- Since this is a dev tool, git being installed is a safe assumption

### Perplexity Research: Safety of Temp Git Repos for Testing

We consulted Perplexity about safety concerns with creating temp git repos for testing:

- **Safety**: Git operations are completely isolated to the `.git` directory they run in. Zero risk of propagation to parent/real repos.
- **Nested repos**: `git rev-parse --show-toplevel` from a nested temp repo correctly returns the temp repo's root. No performance issues even with hundreds.
- **Recommendation**: Use `os.tmpdir()` instead of nesting inside the project tree - zero nesting concerns, no `.gitignore` needed, OS handles cleanup, scales well. Used by production test suites (go-git, skaffold).

### Perplexity Research: Vitest Temp Directory Auto-Cleanup

We consulted Perplexity about safe auto-cleanup of temp directories:

- Vitest has a built-in `test.extend()` context fixture system for automatic temp dir lifecycle management
- The fixture creates a unique temp dir in `os.tmpdir()` before each test, passes it to the test, and auto-cleans after
- Cleanup is safe because the path is always generated by `fs.mkdtemp()` under `os.tmpdir()` - can never be empty, `/`, or your project dir
- No explicit `rm -rf` commands scattered across test files
- Source: [sdorra.dev/posts/2024-02-12-vitest-tmpdir](https://sdorra.dev/posts/2024-02-12-vitest-tmpdir)

## Appendix I - Sample Source Code For The Vitest Temp Dir Fixture

Source: [Vitest Test Context docs](https://vitest.dev/guide/test-context) and [sdorra.dev blog post](https://sdorra.dev/posts/2024-02-12-vitest-tmpdir)

### How It Works

Vitest's `test.extend()` lets you define **fixtures** - setup/teardown logic that runs automatically for each test. The fixture:
1. Creates a unique temp dir in `os.tmpdir()` **before** each test
2. Passes the path to the test function as a named parameter
3. Cleans up the temp dir **after** the test completes (even if the test fails, via `finally`)

No changes to `vitest.config.ts` are needed - `test.extend()` works out of the box.

### Where The Fixture File Goes

Convention is to put reusable fixtures in a `fixtures.ts` file alongside or near the tests:

```
tests/
├── e2e/
│   └── demo/
│       ├── fixtures.ts                                          <-- fixture definition
│       └── quick-jira-workflow-produces-expected-files.e2e.test.ts  <-- imports from fixtures.ts
```

### Fixture File: `tests/e2e/demo/fixtures.ts`

```typescript
import { test as base } from 'vitest';
import { execSync } from 'node:child_process';
import { mkdtempSync, rmSync } from 'node:fs';
import { tmpdir } from 'node:os';
import { join } from 'node:path';

/**
 * Custom test context providing a temp directory that is:
 * - Created in os.tmpdir() (completely outside the project tree)
 * - Initialised as a git repo (git init)
 * - Automatically cleaned up after each test
 */
interface TempGitDirFixture {
  tempGitDir: string;
}

export const test = base.extend<TempGitDirFixture>({
  // eslint-disable-next-line no-empty-pattern -- Vitest fixture signature requires this
  tempGitDir: async ({}, use) => {
    // Create unique temp directory in OS temp (e.g. /tmp/vitest-git-abc123)
    const tempDir = mkdtempSync(join(tmpdir(), 'vitest-git-'));

    // Initialise as a git repo so git rev-parse --show-toplevel works
    execSync('git init', { cwd: tempDir, stdio: 'ignore' });

    try {
      // Pass the temp dir to the test - test runs during this call
      await use(tempDir);
    } finally {
      // Auto-cleanup after test completes (even on failure)
      // Safe because path is always generated by mkdtempSync under os.tmpdir()
      rmSync(tempDir, { recursive: true, force: true });
    }
  },
});
```

        tempGitDir, 'docs', 'jira-docs', testJiraId,
        'workflow-docs', '01-read-jira-implement-and-mark-as-done.summary.md'
