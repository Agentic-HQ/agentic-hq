# Plan: AHQ-107 GREEN — Add `ahq-workflow.json` Creation to `create-workflow` Workflow

## Context

AHQ-103 introduced a requirement that every AHQ workflow have an `ahq-workflow.json` metadata file in its skill directory. All existing workflows were updated. The **`create-workflow` workflow — which builds NEW workflows on demand — was not updated**. This Jira closes that gap so that new workflows generated by `create-workflow` automatically include the required metadata file.

Scope (per updated Jira and AI-summary Q&A): edit all **five** command files in `.agentic-hq/plugins/agentic-hq-core-plugin/commands/create-workflow/`. Two new pieces of info must be collected from the user (`workflow-short-id` + `exampleParameters`), `workflow-short-id` flows through the command-output-string chain, `exampleParameters` flows through the DRAFT/APPROVED spec (per Q1 human answer), and Command 03 gains a metadata validation check.

Test type = `manual`. Human has explicitly stated: "No need to test this create-workflow workflow again after you've made this change — I'll be using it again soon and will confirm it works and fix it if it doesn't." → **No automated tests will be written or run** for this GREEN phase. Verification is by reading the edited files.

**2.4 Step 5 — Collaboratively Create DRAFT Workflow Spec:** Insert a new subsection at the start of the "Collaboration Process" describing how to elicit and enforce `exampleParameters`:

> ### Discussing Parameters and `exampleParameters`
>
> Before drafting the spec, work with the user to decide whether the new workflow should accept any CLI parameters.
>
> - Use the Full Jira workflow as a concrete example: `agentic-hq full-jira -- --jira-id=AHQ-107`. Everything after the `-- ` is a passthrough parameter the user's TypeScript CLI receives directly.
> - If the workflow takes parameters, produce an `exampleParameters` string that starts with `-- ` (the passthrough marker), e.g. `"-- --jira-id=AHQ-107"`.
> - **CRITICAL**: `exampleParameters` MUST always start with `-- ` when it's non-empty. This is the convention that makes them passthrough parameters.
> - **If the workflow takes NO parameters**, set `exampleParameters` to the empty string `""`. This matches the convention used by existing parameter-less workflows (e.g. `create-workflow`).
> - Record the decided value under the new "Workflow Metadata" section of the DRAFT spec (see template below). Command 02 will read it from the spec when creating `ahq-workflow.json`.

## Workflow Metadata
